Semantica 以开放方式构建，贡献者来自众多领域的研究人员、工程师和从业者。无论你是提交 bug、分享项目，还是审阅 PR：你都是生态系统的一部分。


## 获取帮助

- [GitHub Issues](https://github.com/semantica-agi/semantica/issues)：提交包含完整上下文的 bug 报告和功能请求。
- [GitHub Discussions](https://github.com/semantica-agi/semantica/discussions)：提问、分享想法并讨论设计决策。
- [Pull Requests](https://github.com/semantica-agi/semantica/pulls)：浏览开放的贡献并提交你自己的 PR。
- [Security Issues](https://github.com/semantica-agi/semantica/security/advisories/new)：私下报告漏洞（切勿在公开 issue 中报告）。


## 社区准则

我们遵循 [Contributor Covenant Code of Conduct](https://github.com/semantica-agi/semantica/blob/main/CODE_OF_CONDUCT.md)。社区建立在四项原则之上：

- **尊重**：以善意和耐心对待每个人，无论其经验水平如何
- **包容**：欢迎所有背景、领域和方法
- **协作**：共同寻求更好的解决方案，而非在方法上相互竞争
- **学习**：公开分享知识，毫不犹豫地提问，并帮助他人成长

如需报告不可接受的行为，请创建带有 `[CoC]` 前缀的 GitHub issue。每份报告都会被调查。


## 参与贡献的方式

没有唯一正确的贡献方式。选择适合你技能和时间的方向：

### 代码

- 修复标记为 [`good-first-issue`](https://github.com/semantica-agi/semantica/labels/good-first-issue) 的开放 bug
- 添加新功能或集成
- 改进性能或重构现有模块

### 文档

- 修正指南中的拼写错误并提升清晰度
- 为 API 参考添加示例
- 编写领域特定的 cookbook notebook

### 测试

- 为未覆盖的模块增加测试覆盖
- 复现并确认已报告的 bug
- 提升跨平台的测试可靠性

### 社区

- 在 issue 和 discussion 中回答问题
- 审阅开放的 pull request
- 在 GitHub Discussions 中分享你的 Semantica 项目

完整的开发工作流请参阅[贡献指南](/zh/contributing-guide)。
